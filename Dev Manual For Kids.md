# Klipper Plugin Manager: как написать и установить свой плагин

Пошаговая инструкция: от запуска менеджера до готового плагина с настройками в веб-интерфейсе.

## 1. Что это и зачем

**Klipper Plugin Manager** (`klipper_plugin_manager.py`) - маленький веб-сервис, который устанавливает «плагины» (extras) в Klipper без ручного копирования файлов по SSH.

**Плагин** - это один Python-файл. Klipper загружает его как модуль и получает новые G-код команды, датчики, проверки и т.д.

При установке менеджер сам делает всё скучное:

1. проверяет файл (имя, размер, синтаксис, наличие `load_config`);
2. кладёт его в `~/printer_data/config/extras/`;
3. создаёт симлинк в `~/klipper/klippy/extras/`, чтобы Klipper нашёл плагин;
4. добавляет файл в `.git/info/exclude`, чтобы Moonraker не ругался на «грязный» репозиторий Klipper;
5. берёт пример настроек из комментария в начале плагина и сохраняет его в `extras/<имя>.cfg`;
6. один раз добавляет в начало `printer.cfg` строку `[include extras/*.cfg]` (с резервной копией `printer.cfg.bak-<дата>`).

Вам остаётся: написать файл, нажать «Установить», проверить настройки, перезапустить Klipper.

> **Важно.** Плагин - это код, который Klipper выполняет на вашей машине. Ставьте только то, что написали сами или прочитали целиком.

## 2. Запуск менеджера

Зависимости не нужны, только Python 3.7+ (стандартная библиотека).

```bash
python3 klipper_plugin_manager.py --port 8088
```

При первом запуске создаётся токен доступа, он выводится в консоль и хранится в `~/.klipper_plugin_manager_token`. Откройте `http://<адрес-принтера>:8088`, браузер один раз спросит токен и запомнит его.

### Параметры запуска

| Параметр | По умолчанию | Для чего |
| --- | --- | --- |
| `--host` | `0.0.0.0` | на каком адресе слушать |
| `--port` | `8088` | порт |
| `--config-dir` | `~/printer_data/config` | где лежит `printer.cfg` |
| `--klipper-dir` | `~/klipper` | где установлен Klipper |
| `--moonraker` | `http://127.0.0.1:7125` | адрес Moonraker (нужен для кнопки перезапуска) |
| `--token-file` | `~/.klipper_plugin_manager_token` | файл с токеном |

Если у вас нестандартные пути (например, старый Klipper с `~/klipper_config`), укажите `--config-dir` и `--klipper-dir`.

### Автозапуск (пример для systemd)

Создайте файл `/etc/systemd/system/klipper-plugin-manager.service`, поправив пользователя и пути:

```ini
[Unit]
Description=Klipper Plugin Manager
After=network.target

[Service]
User=pi
ExecStart=/usr/bin/python3 /home/pi/klipper_plugin_manager.py --port 8088
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Затем: `sudo systemctl enable --now klipper-plugin-manager`. Токен смотрите командой `cat ~/.klipper_plugin_manager_token`.

### Безопасность

Доступ к менеджеру равен удалённому выполнению кода на принтере. Держите его только в доверенной локальной сети, не пробрасывайте порт в интернет и не показывайте токен посторонним.

## 3. Как установить плагин

На странице менеджера есть два способа:

- **Загрузить файл .py**: выберите файл на компьютере и нажмите «Установить».
- **Установить по ссылке**: вставьте ссылку на файл, например `https://github.com/user/repo/blob/main/plugin.py`. Ссылки вида `github.com/.../blob/...` менеджер сам превращает в «сырые».

После установки появится сообщение вроде: «Установлен my\_plugin.py. Секция \[my\_plugin\] добавлена в extras/my\_plugin.cfg. Проверьте настройки и перезапустите Klipper».

Дальше:

1. Нажмите **«Настроить»** у плагина, проверьте и поправьте настройки.
2. Нажмите **«Перезапустить Klipper»** (не делайте этого во время печати: она прервётся).
3. Если Klipper запустился без ошибок, плагин работает.

## 4. Свой плагин за 5 минут

### Правила для файла

| Правило | Пример |
| --- | --- |
| Имя файла: латиница, цифры, `_`, начинается с буквы, заканчивается на `.py` | `my_plugin.py` |
| Имя файла = имя секции в конфиге | `my_plugin.py` -> `[my_plugin]` |
| Размер не больше 256 КБ |  |
| Кодировка UTF-8 |  |
| Нет синтаксических ошибок |  |
| В файле есть функция `load_config` в самом начале строки (без отступа) | `def load_config(config):` |
| Имя не совпадает со встроенным модулем Klipper | не `fan.py`, `probe.py`, `heaters.py` |

Совет: чтобы не пересечься со встроенными модулями, давайте файлам уникальные имена (например, `my_hello.py`, `soak_guard.py`).

### Минимальный рабочий плагин

Скопируйте это в файл `hello_plugin.py`:

```python
# hello_plugin - пример: команда HELLO пишет приветствие в консоль.
#
# Пример секции:
#   [hello_plugin]
#   # кого и как приветствовать
#   greeting: Привет
#   repeat: 1

class HelloPlugin:
    def __init__(self, config):
        # объекты Klipper, которые нужны почти всегда
        self.printer = config.get_printer()
        self.gcode = self.printer.lookup_object('gcode')
        # настройки из секции [hello_plugin]
        self.greeting = config.get('greeting', 'Привет')
        self.repeat = config.getint('repeat', 1, minval=1, maxval=10)
        # новая G-код команда
        self.gcode.register_command(
            'HELLO', self.cmd_HELLO, desc='Поздороваться')

    def cmd_HELLO(self, gcmd):
        name = gcmd.get('NAME', 'мир')
        for _ in range(self.repeat):
            gcmd.respond_info('%s, %s!' % (self.greeting, name))

    # необязательно: значения, доступные в макросах
    def get_status(self, eventtime):
        return {'greeting': self.greeting}


def load_config(config):
    return HelloPlugin(config)
```

Установите его через менеджер, перезапустите Klipper и выполните в консоли `HELLO NAME=Вася`. Должно появиться «Привет, Вася!».

В макросах значение доступно как `{printer.hello_plugin.greeting}` (это работает благодаря методу `get_status`).

### Из чего состоит любой плагин

1. **Класс** с методом `__init__(self, config)`. Здесь читаются настройки и регистрируются команды.
2. **Функция `load_config(config)`**, которая возвращает объект класса. Klipper вызывает её сам, когда видит секцию `[имя_файла]`.
3. Необязательно: метод `get_status(self, eventtime)`, который возвращает словарь значений для макросов и веб-интерфейса.

## 5. Шапка с примером настроек

Менеджер умеет **автоматически создавать конфиг плагина**. Для этого в начале файла (в первых 120 строках) нужен комментарий в таком формате:

```python
# Описание плагина в свободной форме.
#
# Пример секции:
#   [my_plugin]
#   option_one: 10
#   # комментарий к опции
#   option_two: True
```

Правила:

- Первая строка блока - имя секции в квадратных скобках **одна на строке**, после `#` минимум **два пробела**: `#   [my_plugin]`.
- Следующие строки с настройками тоже начинаются с `#` и минимум двух пробелов. Блок заканчивается на первой строке, которая не подходит под этот шаблон (например, на пустой строке `#`).
- Комментарии внутри блока пишутся как `#   # текст`: они попадут в конфиг как `# текст`.
- Отступ (лишние пробелы) при сохранении убирается, получится обычная секция без отступов.
- Не пишите раньше этого блока другие строки вида `#   [что-то]`: менеджер возьмёт первую подходящую.

Что произойдёт при установке:

- Если файла `extras/<имя>.cfg` ещё нет, менеджер создаст его из примера.
- Если ваш `printer.cfg` уже содержит такую же строку секции, менеджер ничего не добавит и напишет об этом.
- При обновлении плагина существующий `.cfg` **не перезаписывается**: ваши правки сохранятся.
- Если блока в шапке нет, но в файле есть `load_config`, будет создан пустой `[имя]`. Для плагинов только с `load_config_prefix` без блока в шапке конфиг не создаётся.

Чтобы пользователю было проще, **пишите в примере рабочие значения** и поясняйте опции комментариями.

## 6. Шпаргалка по API Klipper

### Чтение настроек

```python
config.get('name')                       # обязательная строка
config.get('name', 'по умолчанию')       # необязательная
config.getint('n', 5, minval=1, maxval=100)
config.getfloat('t', 40., above=0.)      # строго больше 0
config.getboolean('enabled', True)
config.getchoice('mode', {'a': 'a', 'b': 'b'}, 'a')
```

**Все** опции, которые поддерживает плагин, нужно прочитать в `__init__`, даже если значение не используется. Иначе Klipper при запуске скажет, что опция «не является допустимой» (так он ловит опечатки пользователей).

Ошибка в настройках: `raise config.error('Понятное описание')`. Klipper покажет её при старте.

### G-код команды

```python
gcode = self.printer.lookup_object('gcode')
gcode.register_command('MY_CMD', self.cmd_MY_CMD, desc='Описание')

def cmd_MY_CMD(self, gcmd):
    n = gcmd.get_int('COUNT', 1, minval=1)       # MY_CMD COUNT=3
    x = gcmd.get_float('X', 0.)
    s = gcmd.get('NAME', 'abc')
    gcmd.respond_info('Готово')                   # сообщение в консоль
    raise gcmd.error('Что-то пошло не так')       # ошибка (прервёт печать)
```

Имена команд пишите ЗАГЛАВНЫМИ буквами и с префиксом плагина (`SOAK_START`, а не `START`), чтобы не пересечься с другими.

### Получить другой объект Klipper (датчик, нагреватель, стол)

Делайте это **не в `__init__`, а в событии `klippy:connect`**: на момент `__init__` остальные секции могут быть ещё не загружены.

```python
class MyPlugin:
    def __init__(self, config):
        self.printer = config.get_printer()
        self.sensor_name = config.get('sensor')       # temperature_sensor frame
        self.printer.register_event_handler('klippy:connect', self._connect)

    def _connect(self):
        self.sensor = self.printer.lookup_object(self.sensor_name, None)
        if self.sensor is None:
            raise self.printer.config_error('Не найден ' + self.sensor_name)

    def temp(self):
        eventtime = self.printer.get_reactor().monotonic()
        return self.sensor.get_status(eventtime)['temperature']
```

У нагревателей (`heater_bed`, `extruder`) метод `get_status` возвращает ещё и `'target'`.

### События

| Событие | Когда |
| --- | --- |
| `klippy:connect` | всё загружено, можно искать другие объекты |
| `klippy:ready` | принтер готов к работе |
| `klippy:shutdown` | аварийная остановка |
| `klippy:disconnect` | выключение/перезапуск |

```python
self.printer.register_event_handler('klippy:ready', self._ready)
```

### Периодические задачи (таймер)

```python
self.reactor = self.printer.get_reactor()
self.timer = self.reactor.register_timer(self._tick, self.reactor.NEVER)
# включить в событии klippy:ready:
self.reactor.update_timer(self.timer, self.reactor.NOW)

def _tick(self, eventtime):
    # короткая работа, без ожиданий!
    return eventtime + 2.0        # когда вызвать снова (через 2 с)
    # return self.reactor.NEVER   # или остановить таймер
```

### Ожидание внутри G-код команды

В обработчике команды можно ждать, как это делает `M190`:

```python
def cmd_WAIT(self, gcmd):
    reactor = self.printer.get_reactor()
    while not self.done():
        if self.printer.is_shutdown():
            raise gcmd.error('Klipper остановлен')
        reactor.pause(reactor.monotonic() + 1.)   # не time.sleep()!
```

Никогда не используйте `time.sleep()`: он замораживает весь Klipper.

### Значения для макросов

```python
def get_status(self, eventtime):
    return {'ready': self.ready, 'temp': self.temp()}
```

В макросе: `{% if printer.my_plugin.ready %} ... {% endif %}`.

### Несколько экземпляров (`[my_plugin имя]`)

Если нужны несколько секций одного плагина, добавьте функцию:

```python
def load_config_prefix(config):
    name = config.get_name().split()[-1]     # 'имя' из [my_plugin имя]
    return MyPlugin(config, name)
```

Имя файла остаётся прежним (`my_plugin.py`). Блок с примером в шапке работает и для такого случая: напишите `#   [my_plugin имя]`.

## 7. Золотые правила плагинов

1. **Не блокируйте Klipper.** Никаких `time.sleep()`, долгих циклов и сетевых запросов в таймерах. Для ожидания в G-код команде используйте `reactor.pause()`.
2. **Только стандартная библиотека Python.** Дополнительные пакеты в окружении Klipper обычно не установлены.
3. **Другие объекты ищите в `klippy:connect`**, а не в `__init__`.
4. **Читайте все свои опции в `__init__`.**
5. **Понятные ошибки.** `gcmd.error('...')` и `config.error('...')` с человеческим текстом.
6. **Описывайте плагин и пример настроек в шапке файла** (см. раздел 5).
7. **Префиксы в именах команд.** `MYPLUGIN_DO_THING`, а не `DO_THING`.
8. **Безопасные значения по умолчанию.** Плагин не должен менять поведение принтера, пока пользователь явно его не настроил.
9. **Проверяйте синтаксис до загрузки:** `python3 -m py_compile my_plugin.py`.

## 8. Если что-то пошло не так

### Ошибки менеджера при установке

| Сообщение | Что делать |
| --- | --- |
| «Недопустимое имя файла (латиница, цифры, \_ и .py)» | Переименуйте файл: без пробелов и кириллицы, начинается с буквы |
| «Файл больше 256 КБ» | Плагин слишком большой; уберите лишнее |
| «Файл должен быть в кодировке UTF-8» | Пересохраните файл в UTF-8 |
| «Синтаксическая ошибка, строка N: ...» | Исправьте ошибку в указанной строке |
| «Это не модуль Klipper: нет функции load\_config()» | Добавьте `def load_config(config):` в самом начале строки, без отступа |
| «Имя занято встроенным модулем Klipper: x.py» | Переименуйте файл (и секцию в конфиге) |
| «Не удалось скачать: ...» | Проверьте ссылку и доступ принтера в интернет |
| «Неверный токен» | Введите токен из `~/.klipper_plugin_manager_token` |
| «Не найден printer.cfg» | Укажите правильный `--config-dir` |
| «Moonraker недоступен» | Проверьте `--moonraker`, перезапустите Klipper вручную |

В таблице плагинов статус **«конфликт имён»** означает, что в `klippy/extras` уже есть файл с таким именем, который менеджер не устанавливал. Статус **«не подключён»** означает, что симлинк пропал: установите плагин заново.

### Ошибки Klipper после перезапуска

Текст ошибки виден в Mainsail/Fluidd, подробности в `~/printer_data/logs/klippy.log` (ищите последние строки со словами `Error` и `Traceback`).

| Что видите | Причина |
| --- | --- |
| `Section 'xxx' is not a valid config section` или `Unable to load module 'xxx'` | Плагин не установлен или имя секции не совпадает с именем файла |
| `Option 'abc' is not valid in section 'xxx'` | Опция записана в конфиге, но не прочитана в `__init__` (или опечатка) |
| `Option 'abc' in section 'xxx' must be specified` | Обязательная опция не задана |
| `Traceback ... SyntaxError / NameError` | Ошибка в коде плагина |
| Команда не найдена | Забыли перезапустить Klipper или `register_command` не вызван |

## 9. Обновление и удаление

- **Обновить плагин**: загрузите новую версию файла с тем же именем. Файл заменится, ваш `extras/<имя>.cfg` останется нетронутым. Затем перезапустите Klipper.
- **Изменить настройки**: кнопка «Настроить» у плагина, затем перезапуск Klipper.
- **Удалить плагин**: кнопка «Удалить». Менеджер удалит файл, симлинк, запись в `.git/info/exclude` и `extras/<имя>.cfg`. Если секция плагина была прописана в `printer.cfg` вручную, удалите её сами, иначе Klipper не запустится. Затем перезапустите Klipper.

## 10. Чек-лист перед установкой

- [ ] Имя файла: латиница, цифры, `_`, заканчивается на `.py`
- [ ] Имя файла совпадает с именем секции, а оно не занято встроенным модулем
- [ ] В файле есть `def load_config(config):` без отступа
- [ ] Все опции читаются в `__init__`
- [ ] В шапке есть блок `#   [имя_секции]` с примером настроек
- [ ] Нет `time.sleep()`, внешних пакетов и блокирующих циклов в таймерах
- [ ] `python3 -m py_compile ваш_файл.py` проходит без ошибок
- [ ] Печать не идёт: можно спокойно перезапускать Klipper
